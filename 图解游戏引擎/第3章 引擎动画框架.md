
### 1. 骨骼动画原理

- 基本原理是**通过骨骼层级结构驱动三维模型的顶点变形**

- **分为四步**：

	1. **搭建骨骼结构**：骨骼节点通过父子关系连接成树状结构
	
	2. **绑定模型和骨骼**：Binding。每个顶点被分配对应骨骼节点和权重值，决定受骨骼节点运动的影响程度
	
	3. **创建关键帧动画**：设置骨骼节点的位移、旋转等变换参数
	
	4. **蒙皮计算**：通过骨骼节点驱动模型顶点动态变形。通过顶点所关联骨骼节点的变换矩阵乘上对应权重值，再求和，求出最终变换矩阵

- 每个骨骼节点都有自身的局部变换，由位移、旋转、缩放组成，简称**TRS**

	- 局部变换指其相对父节点的变换，全局变换则相对于世界坐标系
	
	- 进行蒙皮计算前，要将局部变换矩阵转换为全局变换矩阵
	
	- 蒙皮计算过程：
		
		1. 首先连乘当前骨骼节点及其所有父节点的TRS，得到全局变换矩阵
		
		2. 再对其求逆，得到偏移变换矩阵
		
		3. 将一个顶点先通过偏移变换矩阵变换到全局坐标系，再通过每帧更新的全局变换矩阵将其变换回世界空间

- 模型在绑定骨骼时采用的**初始姿态**通常被称为 T-Pose

	- T-Pose 矩阵即绑定姿态下全局变换矩阵的逆，所以可以离线预计算
	
- **骨骼动画混合：** 主要是为了处理不同动作带来的骨骼位姿冲突
	
	- 主要过程：先计算所有骨骼的变换矩阵，再球加权平均值，最后乘以T-Pose，得到全局变换矩阵

- **网格动画混合：** 在多个预先制作的网格之间进行插值

	- 每个预设的目标网格都会包含一组相对于基础网格的顶点偏移量
	
	- 过程：遍历每个混合网格，对各混合网格对应顶点位置进行加权求和，进而计算得出每个顶点的最终位置
	
	- 不同模型的顶点数量和拓扑结构需要保持一致

- **Root Motion根运动**：基于角色骨骼中根骨骼的位移与旋转来驱动角色运动

	- Unity / UE 支持从动画播放中获取某个骨骼节点的速度/加速度，用于匹配业务逻辑
	
	- Unity 中，系统会计算当前帧和上一帧之间 Root Node 的变化量并提取增量
	
	- 可以理解为：根据指定骨骼节点逐帧计算增量变换，从而确定角色整体速度和目标位置

### 2. Unity 的动画原理

#### 2.1 Animation 组件

- 主要包括**混合动画、队列动画、动画事件**和**动画轨道**的播放

- 核心逻辑为**播放队列**、**动画播放状态**和**动画事件**

	- `AnimationState` 实例 与 `AnimationClip` 一一对应，用于帧数据更新和动画轨道更新
	
	- 但并不负责骨骼变换矩阵的计算和蒙皮计算

- **动画采样**：从 Clip 中获取当前帧数据，再通过插值、曲线等方式做平滑计算

	- 包括更新动画时间、处理动画逻辑（事件、权重计算等）、处理动画队列、以及动画采样与混合

- 支持**可见性剔除**：进入相机视锥体时播放，反之暂停
	
	- 通过监听 Renderer 上的可见性事件来实现这一点

#### 2.2 Animator 组件

- 基于 Mecanim 动画系统构建，主要用于实现复杂的角色动画需求
	
	- 通过引用 Animator Controller 来定义游戏对象的动画状态及状态间的过渡逻辑

- **工作机制**

	- 与 Avatar、 Controller 及 PlayableGraph 共同构成动画运行机制
	
	- 内部以 PlayableGraph 为桥梁连接不同的系统，实现动画的播放、更新与管理
	
	- `Avatar` 负责处理与骨骼相关的数据和算法、包括骨骼结构、标准骨骼及其他骨骼相关计算
	
	- `Animator Controller` 用于控制动画播放逻辑，主要涉及状态机、动画层级、参数等
	
	- `PlayableGraph` 负责连接和管理动画控制数据，允许通过脚本动态创建、销毁或修改 Playable 单元
	
		- **PlayableGraph 的更新逻辑**
		
			- 先动态处理 `Animator` 和 `Timeline` 中 `Playable` 的新增和删除
			
			- 再更新 AC 的状态机逻辑，包括动画状态切换与 `BlendTree` 混合数据计算
			
			- 最后处理动画曲线数据，对 `AnimationClipPlayable` 进行帧数据采样与插值计算

- 蒙皮渲染与计算：由 SkinnedMeshRenderer 负责，独立于动画系统

	- 分为 CPU 和 GPU 蒙皮
		
		- GPU 蒙皮中，顶点数据和顶点变换矩阵数据会被传入 GPU 进行计算，开销较大
	
	- 蒙皮计算流程参考之前的 动画数据更新流程，这里被 Job 多线程加速
	
		1. 计算骨骼权重：1根-顶点位置；2根-开启法线；4根-开启切线
		
		2. 准备和原始网格大小相同的缓冲区
		
		3. 先一次性遍历所有骨骼节点加速计算，再根据骨骼变换矩阵和Pose矩阵进行蒙皮计算
		
		4. 蒙皮计算，即顶点和矩阵相乘，各顶点之间没有依赖关系，可被多线程加速
		
		5. 若受多个骨骼影响，还会乘以各个骨骼的权重值，最后取线性均值
	
	- 其网格数据除了顶点、索引、子网格外，还包括 Pose 骨骼矩阵数据和骨骼权重数据

- 其他话题

	- 动画的序列化与反序列化：Unity 中 AnimationClip 的数据最为重要，有Transform数据、Float数据、PPtr对象脚本数据、Event事件数据等
	
	- **动画压缩：**
	
		- 降低采样频率：60fps - 30fps
		
		- 剔除冗余的动画数据：如无意义的Scale曲线
		
		- 隔帧移除、分块压缩、移除关键帧曲线数据
		
		- 按位压缩：把动画数据打包到按时间排序的数组中，以此优化缓存利用率
		
		- 线性帧移除：帧与前后两个关键帧数据差距小的话
		
		- 精度压缩、移除琐碎帧、长岭压缩
		
		- ACL动画压缩：Unity采用的主流算法之一，运用上述多种压缩技术
